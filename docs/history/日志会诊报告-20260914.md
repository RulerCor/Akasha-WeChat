## 1. 长篇大论、沉浸在自己的世界 —— 主因是上下文爆炸，不是人设

**铁证**：18:23:58 群里的 `/stats` 返回

```
📊 Conversation Token usage (ID: aefe4248...)
Total:          1,224,323        ← 122 万 token
Input (cached):   845,822
Input (other):    371,166
```

**根因**：`agent_runner.config.compression.max_turns = -1`
—— 表示**永不按轮数截断**，对话历史无限累积。模型塞进 122 万 token 后注意力涣散，
开始把历史里翻出来的东西当成"当下话题"往外倒。

**典型症状**（18:20:05，洛辰说"小m3沉浸在自己的世界里也很可爱哦"）：

> 呜喵……洛辰又夸我了……沉浸在自己世界里的我也很可爱吗，呜……
> 而且听到你们说"阿米诺斯"，我刚才又想起好多罗德岛的事情呢。锡人的笑话好冷哦，
> 但陪着博士的时光很温暖；莱欧斯的沙虫肉丸听起来怪怪的……诗怀雅、拜松、熊熊、
> 臭老鼠（林雨霞）他们最后还是去吃了车仔面，扑街龙（陈）还在山沟里蹭信号呢……

—— 整段和当前话题无关，是"回忆模式"。这就是 122 万 token 上下文的典型表现。

**已修**：`max_turns: -1 → 30`。下次对话即硬截断到最近 30 轮，
**不用清空历史、不丢近期记忆**，也立刻把 122 万砍下来。

放大观感的次要因素：`segmented_reply.enable=true`（>150 字按句拆成多条，
间隔 0.5–1.5 秒连发），一条长回复在群里看起来就是"刷屏"。

## 3. "每次发消息都被回" —— 错觉 + 一个真 bug

三个来源叠加：

1. **私聊本来就是每条必回**（私聊没有"主动回复"概念，每条都是直接对话）。
   你在私聊里测功能，自然 100% 有回应。
2. **群聊非 @ 只有 7.7%**，但 `reply_with_mention=true` 会让被插话的人收到 @ 强提醒，
   体感上像"专门回复我"。
3. **真 bug**：`at` 段和 `reply` 段在桥接出站时被**静默丢弃**。

第 3 点印证了你的观察"**并没有 @**"——

`ob_protocol.py` 的出站循环只处理 `reply / text / image / file / face` 五种段，
`at` 不在其中，直接被丢掉；`reply` 段也因为 `quote_reply_prefix=false` 而被忽略。
所以群里看到的回复是**既没有 @、也没有引用**的裸文本。
