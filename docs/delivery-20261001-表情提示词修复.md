# 交付说明 — 2026-10-01 表情包提示词全情绪化 + 注入优先级修复

对应 `CHANGELOG.md` 同日章节。git 提交 `8ebcba9`。

## 根因（与 9-30 诊断的接续）

前一天证明「名单已到达模型、模型仍 0 调用」。深挖 companion 插件发现：

- 每轮被动聊天，companion 注入「被动回复边界」指令，其中
  **「请直接输出一次最终正文」落在系统提示最末尾**
  （其注入计划 `render_into` 在 priority=-240000 执行并追加到末尾）；
- flash 级模型对系统提示末尾注意力最强 → 整轮按纯文本输出；
- 这解释了「主动任务（早报/晚安）工具全正常、被动聊天 50 工具 0 调用」。

## 修复

- 注入钩子 priority `1000 → -300000`（companion 最低 -260000，本钩子最后执行），
  规则追加到系统提示最末尾、紧贴边界指令之后；
- 规则改**全情绪鼓励型**并显式声明优先于「直接输出正文」：
  开心/震惊/疑惑/生气/哭泣/委屈/无语/心疼/安慰/打气都是好时机，
  情绪到位先发一张贴合表情再输出文字，一次最多一张；
- 工具 docstring 同步鼓励型（示例：嚎啕大哭/疑惑问号/加油打气/委屈含泪）。
