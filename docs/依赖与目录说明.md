# 依赖与目录说明

> **一句话**：这个文件夹是**自包含的开发环境**。AstrBot 框架的全部代码、两个 venv、
> 基座 Python、WeFlow 程序本体都在里面；**只有微信和 Ollama 在外部**。
>
> 最后更新：2026-09-17

---

## 一、为什么要有这份文档

以前项目的依赖散落在各处（WorkBuddy 自带的 Python、`%LOCALAPPDATA%` 里的 WeFlow），
换个文件夹、换台机器就起不来，而且谁也说不清"到底依赖了哪些外部东西"。
现在**能收进来的都收进 `vendor/`**，并在本文件里逐项列清楚。

---

## 二、文件夹里有什么

```
Akasha-Wechat_RC/
├── wechat-weflow-bridge-ob11/   ★ 桥接【源码副本】——改代码改这里
├── runtime/                     ★ 本地运行环境（不入库）
│   ├── bridge/                  桥接【运行副本】+ 自己的 venv + 配置 + 数据
│   └── astrbot/                 AstrBot【运行副本】+ 自己的 venv + 配置 + 数据
├── vendor/                      ★ 随项目走的第三方依赖（不入库，约 750MB）
│   ├── python/                  免安装 Python 3.13.14（基座解释器）
│   └── weflow/                  WeFlow 程序本体（Electron）
├── sim/                         微信对话模拟器（不打扰真实会话地测机器人）
├── scripts/                     工具脚本：打包 / 补丁 / 脱敏 / 诊断 / 自检
├── docs/                        文档（含本文件、开发文档、架构图、测试题库）
├── release/                     发布产物（不入库）
│   ├── versions/vX.Y.Z/         各版本源码快照
│   ├── portable/*.zip           ★ 便携版（给别人用的免安装包）
│   └── newestbuild/             最新一次构建
├── AGENT.md                     给后续维护者/AI 的约定与踩坑全表
├── README.md                    项目说明与快速开始
└── CHANGELOG.md                 逐版本改了什么、为什么
```

**AstrBot 框架的代码在哪**：`runtime/astrbot/.venv/Lib/site-packages/astrbot/`
（它是以 pip 包形式装进那个 venv 的，所以"跟着 venv 走"）。我们对它的改动见
`AGENT.md` 的「核心补丁清单」和 `docs/开发文档.md` §6。

## 三、依赖清单

### ✅ 在文件夹里（自包含，约 750MB）

| 依赖 | 位置 | 体积 | 说明 |
|---|---|---|---|
| 基座 Python 3.13.14 | `vendor/python/` | 39 MB | 两个 venv 的 `pyvenv.cfg` 都指向它 |
| 桥接的 Python 环境 | `runtime/bridge/.venv/` | 26 MB | 依赖已装好，免 pip |
| AstrBot 的 Python 环境 | `runtime/astrbot/.venv/` | 382 MB | **AstrBot 框架代码就在这里面** |
| WeFlow 程序本体 | `vendor/weflow/` | 701 MB | Electron 程序，直接能跑 |
| 桥接源码 | `wechat-weflow-bridge-ob11/` | — | 改代码改这里 |

### ❌ 在文件夹外（拿不走 / 不该拿走）

| 依赖 | 位置 | 体积 | 为什么不在文件夹里 |
|---|---|---|---|
| **微信桌面版** | `C:\Program Files\Tencent\Weixin` | 790 MB | 腾讯的软件，需安装 + 手机扫码登录；**无法打包也无法拷贝** |
| Ollama（**可选**） | `%LOCALAPPDATA%\Ollama` + `\Programs\Ollama` | 1.5 G + 2.8 G | 只在"桥接侧做图片转述"时用。`image_caption_model` 留空就完全不需要它 |
| Ollama 模型 | `%USERPROFILE%\.ollama` | 1.1 G | 同上（如 `llava:7b`） |
| WeFlow 的**用户数据** | `%APPDATA%\WeFlow` | 13 MB | ⚠️ **绝不能拷进来**：里面有微信数据库**解密密钥**（`decryptKey` / `imageXorKey` / `imageAesKey`）、`httpApiToken`、`myWxid`。每台机器必须自己生成 |

> **最低要求**：跑起来只需要 **微信**（必装）。Ollama 可以不装。

## 四、开发环境 vs 便携版

两套东西，**共用同一批源码**，用途不同：

| | 开发环境（本文件夹） | 便携版（`release/portable/*.zip`） |
|---|---|---|
| 给谁用 | 你自己开发调试 | **打包给别人** |
| 形态 | 源码 + 运行副本 + vendor | 解压即用的整包 |
| 微信 | 本机已装 | 对方自己装 |
| 模型 Key | 你自己的（在配置里） | **不含**，对方首次配置时填 |
| 数据 | 真实会话 / 定时任务 / 人员名册 | **全部清空并脱敏** |
| WeFlow | `vendor/weflow` 或系统安装 | 内置 `app/weflow` |

**改代码只改 `wechat-weflow-bridge-ob11/`（源码副本）**，然后用
`scripts/sync_to_rc.py` 同步到 `runtime/bridge/` 运行副本。

## 五、怎么重新出便携版

```bash
cd "C:/Users/Junqin Zhao/Documents/Akasha-Wechat_RC"
PYTHONPATH= runtime/bridge/.venv/Scripts/python.exe scripts/build_portable.py
# 产物：release/portable/Akasha-WeChat_便携版-vX.Y.Z.zip
```

脚本会：
1. 从 `vendor/` 取基座 Python 和 WeFlow（**找不到才回落到系统路径**）
2. 从 `runtime/` 取两个 venv
3. 剥掉全部密钥、清空数据库、脱敏文档
4. **对整包跑一遍脱敏审计，有残留就中止出包**
5. 打成 zip

⚠️ **构建时注意**
- 构建目录默认 `C:\_akasha_build`（**必须用短路径**：venv 有近 5 万个小文件，
  放在深目录会撞 Windows 260 字符路径上限）
- 这是**大文件量操作**，沙箱会把写入限速到 ~4 文件/秒 → 要非沙箱执行
- 详见 `AGENT.md` §6

## 六、换台电脑怎么办

**想搬开发环境**：整个文件夹拷过去即可 —— `vendor/python` 在里面，两个 venv 指向它。
但注意：
- `vendor/` 和 `runtime/` 没入库（体积太大），**走 git 是拿不到的**，得整目录拷贝或压缩传
- 微信要在新机器重新装 + 登录
- WeFlow 要在新机器重新配置一次（重新生成本机的解密密钥和 Token）

**只想给别人用**：直接给 `release/portable/Akasha-WeChat_便携版-vX.Y.Z.zip`。
