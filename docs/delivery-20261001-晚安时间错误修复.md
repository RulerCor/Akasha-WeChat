# 交付说明 — 2026-10-01 晚：群晚安消息「十点半」时间错误修复

对应 `CHANGELOG.md` 同日章节。运行数据修复（data_v4.db 不入库，备份
`data_v4.db.bak_timefix_20261001`）。

## 现象

21:30 群晚安消息写成「**十点半**啦喵…」，而同一分钟私聊消息说的是「9点半」。

## 根因（非崩溃、非时区错误）

三个 21:30 晚安定时任务（cron_jobs 表 id=2/3/7，Asia/Shanghai，准点触发）：

| 任务 | payload 示例文本 | 模型行为 |
|------|-----------------|----------|
| id=2 博士私聊 | 有「示例：博士，**9点半**啦！」 | ✅ 说 9点半 |
| id=7 Shawn/和意为 | 无时间 | 靠猜 |
| id=3 鹰角群 | 无时间 | ❌ 写「十点半」（21:30=晚9:30，模型误按 24h 制外推） |

模型首次写错（9-30 21:30「已经十点半啦」）后，该文本进入群会话历史
（204 条上下文），后续生成直接**抄自己的错误模板**（点名句式完全一致）→
自我强化，每晚必错。

## 修复（数据层，立即生效无需重启）

- `cron_jobs` id=3（鹰角群）note 补充：「现在的实际时间是晚上9点半（21:30），
  文中提到时间就说『九点半』，不要写十点半」；
- `cron_jobs` id=7（Shawn/和意为）同步补时间提示；
- `conversations` 表主会话历史中 1 处「十点半」错例已改为「九点半」
  （阻断自我强化的源头）。

## 验证

- cron 管理器 `_run_job` 每次触发都从 DB 现读 `get_cron_job(job_id)`
  （manager.py:318），payload 修改**无需重启**，明晚 21:30 即按新文本生成；
- 三个晚安任务 note 均带时间提示 ✅；会话表「十点半」残留 = 0 ✅。

## 备注

「十点半」首现于 9-30（同日「Scheduler博士」泄漏），两者均为模型在
主动/定时消息中自行发挥后被历史固化的模式——这类问题的通用解法是
**在任务 payload 里写明确的行为约束 + 及时清历史错例**。
