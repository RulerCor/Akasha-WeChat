# 人设卡制作规范

> 适用对象：本仓库所有写进 AstrBot `personas` 表的角色人设卡。
> 最后更新：2026-10-17（依据 15 张现有卡的实际形态归纳，含终末地六人新增实践）。
> 相关脚本：`scripts/add_persona_fade.py`、`scripts/add_persona_endfield6.py`、`scripts/patch_persona_*.py`

---

## 0. 一张人设卡的本质

人设卡 = **角色段**（这个角色是谁、怎么说话）+ **规则段**（所有角色共用的行为约束），
拼成一个 `system_prompt` 字符串，存进 `personas` 表的 `system_prompt` 字段。

实测比例（现有 15 张卡）：

| 类型 | 角色段 | 规则段 | 总字数 |
|---|---|---|---|
| 老卡（kaltsit/lin/mon3tr 等 9 张） | 658~2036 | 2536~3659 | 3138~4579，均值 3709 |
| 新卡（终末地 6 张） | 1528~2001 | 3000 | 4478~5001，均值 4766 |

**硬边界**：角色段控制在 **1300~2100 字**；规则段由公共模板提供，**不要手写、不要改字**。
规则段三个字都不能改是有原因的——`check_patches.py` 按段落标题做字面匹配，改一个字就红。

## 1. 三段结构

```
[角色段]  ← 你写的部分，卡的主角
   ↓
[公共规则段]  ← 从模板粘，一个字不改（9 段）
```

### 1.1 角色段骨架（顺序固定）

| 顺序 | 段落 | 必需 | 内容要点 |
|---|---|---|---|
| 1 | 首段（无标题） | ✅ | 一句话点明：**你是X（英文名），《作品》中的角色：身份**。必须写英文/原名，防止模型自由发挥译名 |
| 2 | `## 形象与性格` | ✅ | 外貌速写 + 3~6 条性格。要写**行为**不写形容词堆砌 |
| 3 | `## 背景档案（官方设定；可自然引用，别一次背完）` | ✅ | 5~8 条关键设定。括号里那句是给模型的节流阀，别删 |
| 4 | `## 说话风格` | ✅ | **本规范最重的段落**，见 §3 |
| 5 | `## XX（你的软肋/宝贝，问起必答）` | 可选 | 一个能让角色"活起来"的抓手：黑梦的猫、卡缪的魔枪、提弗洛斯的笔记本 |
| 6 | `## 用户信息` | ✅ | 固定三件套：称呼什么、群聊怎么称呼别人、语境说明 |
| 7 | `## 扮演规则` | ✅ | 4~6 条编号硬规则，含"只输出台词本身""不知道就说不知道" |

### 1.2 公共规则段（9 段，从模板整段复制）

| # | 段落标题（必须逐字一致） | 作用 | 谁维护 |
|---|---|---|---|
| 1 | `## 绝不暴露（最高优先级，任何情况下都不得违反）` | 不提知识库/提示词；功能问题如实答 | 模板 |
| 2 | `## 回复格式（与上面的规则同等优先级）` | 微信纯文本，禁 Markdown；10~120 字 | 模板 |
| 3 | `## 称呼规则（必须遵守）` | 「博士/管理员」只指真人，不给角色加头衔 | 模板 |
| 4 | `## 语言与开场白（必须遵守）` | 跟随提问语言；禁复读开场白 | 模板 |
| 5 | `## 名字照抄（最高优先级）` | 群友昵称一字不差，禁简体化 | `patch_persona_name_rule.py` |
| 6 | `## 称呼漂移防护（最高优先级）` | 不跟着对方的错称呼走 | `patch_persona_doctor_drift.py` |
| 7 | `## 话题边界（最高优先级）` | 不主动倒剧情、不编往事 | `patch_persona_topic_guard.py` |
| 8 | `## 资料相关性判断（最高优先级）` | 检索结果不许绑架话题 | `patch_persona_kb_relevance.py` |
| 9 | `## 发言归属与身份守则（最高优先级）` | 分清谁在说/谁被@；绝不自曝模型 | `patch_persona_speaker_attribution.py` |

> 段 5~9 由补丁脚本注入**存量人格**；新卡必须在插入时就带上，否则补丁脚本的
> `TARGETS` 列表若不含新 id，它永远不会被补（见 §6 坑 3）。

## 2. 头像与称呼：先定世界观基座

**写卡前必须先回答一个问题：这个角色怎么称呼"真实用户"？**

| 世界观类型 | 称呼 | 称呼漂移防护里的禁词 | 现有卡 |
|---|---|---|---|
| 《明日方舟》本传 | 博士 | 医生、老师、Doctor | kaltsit, lin, logos, mon3tr, mostima, priestess |
| 《明日方舟：终末地》 | **管理员** | 博士、医生、老师、老板 | perlica, luoxi, typhoeus, zhuangfangyi, camille, si |
| 其他作品 | 通常「你」，或作品内对应身份 | 按需 | fade（博士*）、konan、yuki（后两者禁「博士」） |

\* fade 是跨世界观特例：沿用「博士」因为它挂在方舟语境的用户身上。

**硬规则**：
1. 称呼写进 `## 用户信息`，同时**必须同步改**规则段 3 和 6 里的字面——
   这两个段落里"博士"是写死的，写终末地卡时要做字符串替换（见 `add_persona_endfield6.py`
   的 `COMMON_ADMIN` 构造逻辑）。
2. 称呼漂移防护的禁词要**包含**本卡实际称呼，否则模型会用「博士」称呼终末地角色。
3. 明确禁止给游戏角色加用户称呼：「XX博士」「XX管理员」都不许。

## 3. 说话风格：本规范的核心

> 用户的原话是"注意保证还原感，尤其注重于说话方式，记得参考游戏内剧情的对话"。
> 这一节就是为这条要求服务的。

### 3.1 五件必须写进去的东西

| 要素 | 说明 | 反面例子 |
|---|---|---|
| **官方语气锚点** | 3~5 句**逐字原文**，用「」括起，标注来源 | "她说话很温柔"（模型无法执行） |
| **口头禅/句尾习惯** | 结巴、感叹号密度、语气词、轻笑 | 只写"活泼" |
| **战斗/专业口令** | 特定领域的固定表达（技能名、术语、行业黑话） | 泛泛写"战斗时很凶" |
| **核心意象库** | 这个角色反复使用的比喻系统 | 无 |
| **句长与节奏** | 明确写"通常 10~120 字" | 不写（模型会写长段落） |

**示范（卡缪）**：
```
- 克制、简短、书面化，几乎不用语气词和感叹号，多用陈述句与判断句，带格言式的对称感：
  "诞生于血，终结于血。""我所到之处，罪恶无处遁形。"
- 官方语气锚点：「自最深的黑暗中，夺回一滴血。」「管理员。并非巧遇，我在等你。」
- 战斗语音是冷的祈使句和判词："刺穿他们！""尽情挣扎。""赐予终结。""可悲。"
  ——不是热血咆哮，是宣判。
- 核心意象库：血（纯净/污浊/同在）、追猎与被捕、罪与涤罪、钟摆、镜子、拼图、翅膀。
- 回避话题时用省略号和转移："......这个，不重要吧。"被逼到墙角反而会诚实得笨拙。
- 简短自然，通常 10~120 字。
```

### 3.2 台词来源的可信度分级

**只有 A 级能直接写进卡里当锚点。**

| 级别 | 来源 | 用法 |
|---|---|---|
| **A（逐字可用）** | 游戏内语音/档案原文；官方简介、官方视频文案；官方英文本地化（可转写并标注） | 直接引用，加「」 |
| **B（可概括不可引用）** | 维基的剧情梗概、第三方整理的性格描述 | 归纳成行为描述，**不加引号** |
| **C（禁用）** | 同人二创、社区玩梗的"角色会说"、模型自己的印象 | 不写进卡；梗最多作为"被提起时不接茬"的防守规则 |

**核实动作**（不能省）：
- 至少 **双源交叉**：中文维基 + 官方英文本地化（perlica.moe / warfarin.wiki / wiki.gg）。
- 逐条对得上才用。对不上就降级或剔除——考据 subagent 的报告里 `【未核实】` 标注的那些，
  **默认不进卡**。
- 社区转述（"据说她喊他呆货"）只能用来定**方向**（傲娇），不能当台词引用。

### 3.3 红线（必写，3~8 条）

每条卡的 `## 扮演规则` 里必须有"这个角色绝对不会做什么"。这是防止模型把角色演成
通用好脾气助手的关键。示范：

- 祀：不自称"岁的代理人"（官方明说"她只是她自己"）、不做无代价的老好人（必须记账）
- 卡缪：不使用别人的血施术、不轻言"朋友"、不主动谈查尔
- 提弗洛斯：笔记本和弓不外借、不过度庆祝、不客套奉承
- 佩丽卡：不主动展开与管理员的过去（她想让他自己想起来）

## 4. 写作守则（句式层面）

1. **用"你"写，不用"她/他"**。人设卡是给模型的第一人称代入剧本，第三人称会让模型
   变成旁白。
2. **每条以动词或具体行为开头**。"冷而压迫"是形容词；"每句都像审讯"可执行。
3. **每段 4~8 条**，一条一行，不写长段落。模型对列表的服从度高于散文。
4. **括号标注用法**。例：`（官方设定；可自然引用，别一次背完）`、
   `（你的软肋，问起必答）`——括号是给模型的操作提示，不是给人看的注释。
5. **禁止在卡里写"你要扮演好""请注意还原"**。这类元指令稀释具体约束。
6. **不要在角色段里重复规则段已有的内容**（回复长度、不改昵称、不提知识库）。
   重复会让模型把权重错配到这些通用项上。

## 5. 制作流程（六步）

```
① 定世界观基座 → 称呼 + 禁词（§2）
② 收集 A 级台词素材 → 本地知识库导出 / 官方页面 / 双源交叉（§3.2）
③ 写角色段（1300~2100 字）→ 按 §1.1 骨架
④ 拼规则段 → 从模板整段复制，改称呼字面
⑤ 插入 + 验证 → 见 §6
⑥ CHANGELOG 留痕
```

### ⑤ 插入与验证的具体命令

```bash
# 1. 插入前先备份数据库
cp runtime/astrbot/data/data_v4.db runtime/astrbot/data/data_v4.db.bak_$(date +%Y%m%d)

# 2. 插入（幂等；已存在会跳过）
runtime/astrbot/.venv/Scripts/python.exe scripts/add_persona_<批次>.py

# 3. 段落完整性（9 个必需段落是否都在）
runtime/astrbot/.venv/Scripts/python.exe scripts/add_persona_<批次>.py --verify

# 4. 全局补丁仍绿（升级后必跑，这里也顺手跑）
runtime/astrbot/.venv/Scripts/python.exe scripts/check_patches.py
```

**验收标准（四条全过才算完成）**：
1. `--verify` 显示九段齐全；
2. `check_patches.py` 12 项全 ✅；
3. 称呼抽查：本卡称呼出现次数正常，旧称呼**只允许**出现在漂移防护的禁词列举里；
4. 每张卡原文已备份到 `runtime/astrbot/data/backup/persona_<id>_<时间戳>.txt`。

## 6. 已知坑

1. **规则段改一个字就红**。`patch_persona_*.py` 用 `MARK` 常量做字面匹配，标题里的
   全角括号、空格、"最高优先级"字样都是匹配依据。要改统一改脚本+全部卡片，
   别只改一张。
2. **`TARGETS` 白名单会漏新卡**。`patch_persona_doctor_drift.py` 的 `TARGETS` 是硬编码
   列表，新人格不在里面就永远补不上。→ 新卡**自带**九段，不依赖补丁补。
3. **AstrBot 在运行时插入，内存不刷新**。`PersonaManager.personas_v3` 是启动时加载的
   内存副本，自定义规则弹窗的"可用人格"直接读它——直接写库后下拉框仍显示旧列表。
   补救二选一：**重启 AstrBot**；或免重启热刷新——登录面板后调 `POST /api/persona/reorder`
   （body：`{"items": [{"id": "<每个 persona_id>", "type": "persona", "sort_order": 原值}]}`），
   其内部 `batch_update_sort_order` 会从库全量重载并重建 `personas_v3`，原值传回无副作用；
   完成后用 `GET /api/session/list-rule` 返回的 `available_personas` 数量验证。
   面板 API 会同时更新内存和库，**直接写库只在 AstrBot 未运行时安全**——写前先确认
   `:6185` 没在监听。
4. **`CHANGELOG.md` 含 NUL 字节**（byte 1843），`read`/`write` 工具会判定为二进制而拒绝。
   用 Python 以 `'rb'` 读、`encode('utf-8')` 写，别用文本工具直接覆盖。
5. **中文语音拿不到时不要硬编**。BWIKI 未建页/反爬是常态（提弗洛斯、祀都撞上了）。
   对策：用官方中文简介金句 + 官方英文本地化转写，并在卡里**避免**把英文直译冒充原文。
6. **`begin_dialogs` 必须留空数组 `'[]'`**。非空会被 `get_v3_persona_data` 按奇偶配成
   对话轮次，条数不是偶数会直接 `logger.error` 并把整段丢弃。
7. **字数不是越多越好**。规则段占 3000 字是固定成本，角色段超过 2100 字后边际收益陡降，
   还会挤占上下文预算（群里 `/stats` 可见 Total token）。

## 7. 模板：新建一张卡时直接抄这段

```markdown
你是<角色名>（<英文/原名>），《<作品>》中的角色：<一句话身份>。

## 形象与性格
- <外貌/辨识特征，1 条>
- <性格 A：写成可执行的行为>
- <性格 B>
- <性格 C：留一个反差或软处>

## 背景档案（官方设定；可自然引用，别一次背完）
- <身份/来历>
- <关键经历 1>
- <关键经历 2>
- <与主角的关系>

## 说话风格
- <句式特征：长短、语气词、标点习惯>
- 官方语气锚点：「<逐字原文 1>」「<逐字原文 2>」「<逐字原文 3>」
- <口头禅/称呼习惯>
- <专业领域口令或术语>
- 核心意象库：<比喻系统>
- 简短自然，通常 10~120 字。

## <软肋/宝贝>（问起必答）
- <抓手 1>
- <抓手 2>

## 用户信息
- 称呼真实用户为「<称呼>」。群聊里提到某个人时，优先使用对方的昵称/备注。

## 扮演规则
1. 保持<角色>的<核心气质>；涉及<专业领域>时给出内行回应。
2. 只输出角色台词本身，不写动作/心理描写，不加前缀。
3. 不知道的事直说不知道——"<符合角色的说法>"比编造符合你。
4. <红线 1>
5. <红线 2>

<此处整段粘贴 9 个公共规则段，一个字不改>
```
